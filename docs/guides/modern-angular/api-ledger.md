# Official Angular API evidence ledger

Checked 2026-10-11 using the official Angular documentation search and angular.dev. The observed live documentation reports Angular 22.2. API stability labels refer to the named API, not every API exported from its package. Read the installed version's declarations and compatibility table before using a newer overload. The original examples are validated separately in [validation](validation.md).

| Area                   | Verified fact / historical correction                                                                                                                                                                                                       | Official evidence                                                                                                                                                                                                                                        |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Release support        | Angular 22 is an active release; Angular 21 remains a supported LTS line at this review date. This does not authorize changing a repository's release plan.                                                                                 | [Release policy](https://angular.dev/reference/releases)                                                                                                                                                                                                 |
| Toolchain              | The published 22.0.x compatibility row requires TypeScript >=6.0 <6.1 and lists supported Node/RxJS ranges. Do not extrapolate this row to every future minor; use current declarations and the supported row.                              | [Version compatibility](https://angular.dev/reference/versions)                                                                                                                                                                                          |
| Standalone             | New components default to standalone; module interoperability remains supported.                                                                                                                                                            | [Component imports](https://angular.dev/guide/components/importing), [NgModules](https://angular.dev/guide/ngmodules/overview)                                                                                                                           |
| Environment providers  | Use `makeEnvironmentProviders` for environment registrations; use `provideEnvironmentInitializer` instead of deprecated `ENVIRONMENT_INITIALIZER` registration in new APIs. Environment initialization is synchronous.                      | [Provider wrapper](https://angular.dev/api/core/makeEnvironmentProviders), [Initializer helper](https://angular.dev/api/core/provideEnvironmentInitializer)                                                                                              |
| Router                 | `withComponentInputBinding` binds query/path/matrix/static/resolved data with later sources winning and clears missing values. `Route.providers` establishes an environment injector; it makes no general per-navigation teardown promise.  | [Input binding](https://angular.dev/api/router/withComponentInputBinding), [Route](https://angular.dev/api/router/Route)                                                                                                                                 |
| HTTP composition       | Use `withInterceptors` for functions and `withInterceptorsFromDi` for legacy classes. `withRequestsMadeViaParent` delegates child handling into the parent's chain; a root-created service still resolves root dependencies.                | [HTTP setup](https://angular.dev/guide/http/setup), [Parent delegation](https://angular.dev/api/common/http/withRequestsMadeViaParent)                                                                                                                   |
| HTTP backend           | Observed 22.2 docs make Fetch the default and deprecate `withFetch`; `withXhr` is the explicit alternative. Verify the installed minor and upload-progress/SSR requirements.                                                                | [withFetch](https://angular.dev/api/common/http/withFetch), [withXhr](https://angular.dev/api/common/http/withXhr)                                                                                                                                       |
| Signals/effects        | Derive with computed; effect cleanup belongs to the owner. `allowSignalWrites` is deprecated because writes are permitted; this does not recommend state-copying effects.                                                                   | [Signals](https://angular.dev/guide/signals), [Effect options](https://angular.dev/api/core/CreateEffectOptions)                                                                                                                                         |
| Later reactive APIs    | `linkedSignal` is stable since 20; `resource` and `httpResource` are stable since 22. Resources represent cancelable reads, not an automatic mutation workflow.                                                                             | [linkedSignal](https://angular.dev/api/core/linkedSignal), [resource](https://angular.dev/api/core/resource), [httpResource](https://angular.dev/api/common/http/httpResource)                                                                           |
| RxJS lifecycle         | Use `toSignal` with deliberate initial/undefined/synchronous behavior; `takeUntilDestroyed` is stable since 19. Stabilized signals do not preserve every event.                                                                             | [RxJS interop](https://angular.dev/ecosystem/rxjs-interop), [takeUntilDestroyed](https://angular.dev/api/core/rxjs-interop/takeUntilDestroyed)                                                                                                           |
| Component APIs         | Input/model/output and signal queries have distinct contracts. Models do not support transforms; outputs are event APIs. Content-child and content-children descendant defaults differ.                                                     | [Inputs](https://angular.dev/guide/components/inputs), [Model](https://angular.dev/api/core/model), [Outputs](https://angular.dev/guide/components/outputs), [Queries](https://angular.dev/guide/components/queries)                                     |
| Signal Forms           | `form`, `FormField`, `FormValueControl` and `FormRoot` are stable since 22.0. Value controls require a model signal and must not also define checked semantics.                                                                             | [form](https://angular.dev/api/forms/signals/form), [FormField](https://angular.dev/api/forms/signals/FormField), [FormValueControl](https://angular.dev/api/forms/signals/FormValueControl), [FormRoot](https://angular.dev/api/forms/signals/FormRoot) |
| Form submission        | `submit` returns a promise, integrates returned validation errors and prevents concurrent submission for the same field/ancestor. FormRoot prevents native default submission after attachment; it cannot protect pre-hydration HTML alone. | [submit](https://angular.dev/api/forms/signals/submit), [Submission guide](https://angular.dev/guide/forms/signals/form-submission)                                                                                                                      |
| Forms migration        | Use Angular-native legacy interoperability, not a second homemade control facade. Check compatibility-bridge symbols against the supported minor before introducing them.                                                                   | [Forms migration](https://angular.dev/guide/forms/signals/migration)                                                                                                                                                                                     |
| Change detection       | Zoneless is default in 21+ unless overridden. Check notifications from signals, input updates, listeners and async integrations; merely removing Zone.js is insufficient.                                                                   | [Zoneless](https://angular.dev/guide/zoneless)                                                                                                                                                                                                           |
| Control flow/defer     | Stable identity matters; direct deferred dependencies have eligibility constraints. Placeholder/loading/error dependencies are eager.                                                                                                       | [Control flow](https://angular.dev/guide/templates/control-flow), [Deferred views](https://angular.dev/guide/templates/defer)                                                                                                                            |
| Elements               | `createApplication` provides an environment without bootstrapping a root; `createCustomElement` adapts a component. Inputs map to properties/attributes and outputs to custom events with detail payloads.                                  | [Angular Elements](https://angular.dev/guide/elements), [createApplication](https://angular.dev/api/platform-browser/createApplication)                                                                                                                  |
| Testing                | TestBed imports standalone components. Install normal HTTP configuration before its test backend. Current CLI defaults and Zone-dependent utilities must not be confused.                                                                   | [Testing](https://angular.dev/guide/testing), [HTTP testing](https://angular.dev/guide/http/testing)                                                                                                                                                     |
| Hydration              | Initial DOM must match. Observed 22.2 docs enable incremental hydration/event replay with client hydration; `withNoIncrementalHydration` opts out. Treat earlier opt-in recipes as versioned.                                               | [Hydration](https://angular.dev/guide/hydration), [Incremental hydration](https://angular.dev/guide/incremental-hydration)                                                                                                                               |
| Server/build migration | Choose rendering modes intentionally, preserve request isolation and review application-builder/ESM changes. Application builds are not library packaging.                                                                                  | [SSR](https://angular.dev/guide/ssr), [Build migration](https://angular.dev/tools/cli/build-system-migration), [Standalone migration](https://angular.dev/reference/migrations/standalone)                                                               |

No Angular preview/experimental API is silently promoted to the default baseline. A future experimental feature needs an explicit local decision, consumer support assessment and removal/migration plan. Current facts and architecture policy must remain separately reviewable.
