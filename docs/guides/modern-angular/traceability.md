# Source-to-decision traceability

Reviewed source: Manfred Steyer, _Modern Angular_, 2nd Extended Edition, 2024; supplied licensed PDF, **146 physical pages**. The whole document was read, including diagrams, introductory material and end matter. The PDF has six unnumbered front pages; for numbered content, physical PDF page = printed page + 6. Ranges below include chapter endings/continuation pages. C01–C14 are editorial identifiers following the book's fourteen chapters, not new source section numbers. Topic labels are shortened for navigation; descriptions and examples are original.

**S** identifies source concepts, **V** identifies subsequent/version-specific Angular verification, and **A** identifies accepted Anarchitects decisions. The matrix documents coverage, not a claim that the author endorses Angular 22 or Anarchitects policy. “Covered” means mapped to actionable guidance; it does not mean every illustration or code listing is reproduced. API evidence is in the [ledger](api-ledger.md); local applicability and accepted ADR constraints are in [repository application](repository-application.md).

## Coverage maintenance

When an Angular update changes an API, update the ledger, affected example and validation record together. When a local ADR changes, update repository application and the relevant A decision; do not silently synchronize away a local exception. Keep common guide material aligned across repositories while retaining their local application files. Completeness here is chapter/topic traceability, not a claim that every possible Angular feature or every target repository has been runtime-tested.
